# ATO 3.0.1 plan: correctness and reliability

Source: an external source-level review of v3.0.0 (2026-11-20). Every claim was checked against `main` (83f8810) with `npm test` passing (164/164). This file holds the findings, the decisions and what "done" means for each item; the session goal only points here.

## Ground rules

- Branch `fix/3.0.1` from `main`. Commit this plan first (`docs: 3.0.1 plan`).
- One concern per commit, conventional commits, and each commit passes `npx tsc --noEmit` and `npm test` on its own. Check exit codes before committing.
- Anything that closes tabs gets a fast-check property **and** a mutation check: remove the guard, see the property fail, put it back. Write down what you removed and which test failed (in the commit body).
- Every new popup state gets a gallery fixture (`src/dev/fixtures.ts`).
- Keep `core/` pure; Chrome-specific code stays in `ui/chrome-*.ts` and the worker.
- Don't merge, tag, publish or post on GitHub. Run `npm run build` at the end so the user can load `dist/`.
- Order: 0 → 9 as listed. If item 8 grows too large, stop after 7, then do 9 with 8 marked as moved to 3.1.

## 0. Matching modes: no change in behaviour

`src/core/tabs.ts` (`duplicateKey`):

```ts
if (match !== 'ignoreQuery') u.hash = '';   // ignoreHash, ignoreBoth clear the #hash
if (match !== 'ignoreHash') u.search = '';  // ignoreQuery, ignoreBoth clear the ?query
```

This is right, and `src/core/tabs.test.ts:47-49` pins it and passes. The review read the conditions backwards.

**Do:** make the code impossible to misread and add a property so a future "fix" fails:
- Rewrite it the direct way, with the same behaviour: `const dropHash = match === 'ignoreHash' || match === 'ignoreBoth'; const dropQuery = match === 'ignoreQuery' || match === 'ignoreBoth';`
- Add fast-check properties in `tabs.test.ts`: for any URL, under `ignoreHash` two URLs that differ **only in query** never share a key, and two that differ only in hash always do; the reverse for `ignoreQuery`; `ignoreBoth` merges both; `exact` merges neither.
- Mutation check: swap the two conditions, see the properties fail.
- Commit: `refactor: spell out what each match mode drops, with properties`.

## 1. Recheck protection right before closing

**Where:** `src/ui/update.ts` `startClose` (about line 86) filters protected tabs with `protection()` (`src/core/duplicates.ts:41`) when `bulk` is true. Then `app.ts:128-131` waits `CLOSE_ANIMATION_MS` (180 ms) and calls `browser.close(ids)`. `ChromeBrowser.close` (`src/ui/chrome-browser.ts`) takes a fresh snapshot but only drops ids that are gone. It doesn't re-check `active` / `audible` / `splitViewId` / pinned / grouped, so a tab activated during the animation still gets closed.

**Do:**
- Carry the rule into the effect: `{ kind: 'close', tabIds, message, bulk: boolean }` (or a `policy` when bulk). An explicit single close (`bulk: false`) still closes what the user picked, even the active tab. That is intended (comment at `startClose`).
- Add a pure helper in `core/` (e.g. `stillClosable(fresh: Tab[], ids, policy)` in `duplicates.ts`) that returns the fresh tabs among `ids` with `protection(t, policy) === null`. `BrowserPort.close` takes the policy (or a `bulk` flag + policy) and applies it to its fresh snapshot before `chrome.tabs.remove`. Do the same in `FakeBrowser` (`src/dev/`) so the gallery behaves like Chrome.
- The `closed` action must report only the tabs actually closed, so the undo record is exact. The toast message is built in `startClose` before the close; rebuild it from what really closed (e.g. "Closed 3 duplicates · kept 1 that changed"), or have `closed` carry the noun and the skipped count and build the message in `update`.
- Tabs that were skipped must leave `ui.closing` (the `closed` handler at `update.ts:355` only clears returned tabs). Clear every id the effect asked for.
- **Properties** (`ui/update.test.ts` or a new `chrome-browser`/fake test): for any snapshot, any bulk close, and any change to the tabs between deciding and executing (flip active/audible/split/pinned/group), no tab protected in the **fresh** state is closed; `closing` ends empty for the ids requested; the undo list equals the closed set.
- Mutation check: drop the recheck, see the property fail.
- Commit: `fix: recheck protection just before a bulk close`.

## 2. Close failures

**Where:** `app.ts:131`: `void browser.close(...).then(...)` has no rejection path. If `chrome.tabs.remove` rejects (a tab is being dragged, a window is closing), `closed` never arrives and the rows stay in `closing` (hidden or animating) for good.

**Do:**
- Add a `closeFailed` action `{ tabIds }`: clear those ids from `closing` and toast "Couldn't close tabs — try again". Then refresh the snapshot (the runtime already re-snapshots on tab events; also trigger one explicitly).
- Possible partial close: `tabs.remove(array)` can reject after closing some tabs. On failure, re-snapshot and report the requested ids that are gone as `closed` (so undo still covers them), and the rest as failed.
- Do the same review of the other effects (`restore`, `discard`, `move`, `moveTo`): each `void browser.x()` should at least `.catch` and toast, never leave state pending. `restore` already gets `{count}`; make sure a rejected restore toasts too.
- Tests: `app.test.ts` with a `FakeBrowser` whose `close` rejects (and one that closes half, then rejects) → no id stays in `closing`, the error toast shows, and undo covers exactly the closed tabs.
- Fixture: the error toast state in `dev/fixtures.ts`.
- Commit: `fix: recover when closing tabs fails`.

## 3. Undo restores each tab's own history

**Where:** `src/ui/chrome-restore.ts` `restoreTabs`: `recent.findIndex((s) => s.url === tab.url)`. With several closed copies of one URL (ATO's whole use case), each tab may get another copy's back/forward history, or an older, unrelated closed tab with that URL.

**What Chrome gives:** `chrome.sessions.getRecentlyClosed` returns entries newest first. A tab entry's `tab` has `url`, `windowId`, `index`, `sessionId`, and entries have `lastModified` (seconds). **Check in real Chrome** (dev server + chrome-devtools MCP, or a scratch extension page) whether `tab.windowId` and `tab.index` of a closed-tab entry match the original tab's `windowId` and `index`, and write the answer here.

**Do:**
- Score candidates per tab: same URL required; then same `windowId`, then smallest `|index - tab.index|`, then most recent. Use each entry at most once.
- Only consider entries closed at or after the close (store `closedAt` on the undo record: `Date.now()` when `closed` arrives; compare with `lastModified * 1000` with a few seconds of slack). That keeps an unrelated tab closed earlier from being picked.
- Window entries: if a close emptied a window, Chrome records a **window** entry (`s.window`), and the current `flatMap((s) => s.tab ...)` ignores it, so those tabs come back fresh, in the current window, without history. If the closed set is exactly a window entry's tabs, restore the window entry (`sessions.restore(window.sessionId)`). Otherwise fall back as now. Verify in Chrome; this matters for item 4.
- Tests (`chrome-restore.test.ts`, mocked `chrome.sessions`): several closed copies of the same URL across windows and positions each restore from their own entry, exactly once; an older same-URL entry from before the close is never used; a window entry is restored as a window. Keep the existing "each tab back exactly once" property.
- Mutation check: go back to URL-only matching, see the new test fail.
- Commit: `fix: undo restores each tab from its own session entry`.

## 4. Windows view "Close N"

**Where:** `src/ui/windows.ts` button: `Close ${w.tabCount}` with title "Close its tabs (⌫)". The action `closeWindow` (`update.ts:453`) goes through bulk `startClose`, which skips protected tabs (the active tab is always protected), so the window never fully closes and the count is wrong.

**Decision:** keep the safe behaviour and fix the label. Don't add "close the whole window".
- Add `closable: number` to the window model (`ui/model.ts` `WindowGroup`, `derive.ts:148` / `:223`): tabs with `protection(t, policy) === null`, not already `closing`.
- Button: `Close ${closable}`, with title "Close N tabs; M protected stay (⌫)" when M > 0. With `closable === 0`, hide the button (⌫ then toasts "Nothing to close — N protected", as now).
- Fixture with a window where some tabs are protected; check the `aria-label`.
- Commit: `fix: windows view counts only the tabs Close will close`.

## 5. Quoted search: whole words, as documented

**Where:** README line 18: `"exact"` matches whole words. `core/search.ts` `parseQuery` returns `mode: 'exact'` for a quoted phrase, but `searchTabs` only does `haystack.includes`, so `"cat"` matches "catalog".

**Decision:** implement what the README promises: a quoted phrase matches only at word boundaries (letters/digits; use `\p{L}\p{N}` with the `u` flag so non-English text works) and still across spaces in the phrase. Unquoted search stays substring.
- `searchTabs`: when `query.mode === 'exact'`, test with a boundary-aware matcher; `findRanges` gets the same mode so highlights match what matched.
- `dupe:` + quoted phrase goes through the same path (`searchTabs(duplicated, {...query, field: 'all'})` keeps the mode; check it does).
- Tests: `"cat"` matches "my cat" and "cat-food" but not "catalog" or "bobcat"; `"new york"` matches "New York times"; highlights equal the matches; a fast-check property: every exact hit range starts and ends on a word boundary.
- Keep perf: build the regex once per query, not per tab.
- Commit: `fix: quoted search matches whole words, as documented`.

## 6. Privacy wording

Favicons load as `<img src=tab.favIconUrl>`, which can fetch remote http(s) URLs, so "no network requests" isn't strictly true.

**Replace in:** `README.md` (lines 9 and 93), `PRIVACY.md` (lines 11-12), `docs/STORE_LISTING.md` (lines 63 and 107; the store's data-use answers stay "true", only the sentence changes).

**Wording:** "ATO has no analytics, tracking or backend. Your tabs never leave your browser. Favicons are shown from the addresses Chrome provides, so your browser may load them as it would on the tab strip."

Commit: `docs: precise privacy wording (favicons)`.

## 7. Navigation performance: measure, then fix

**Where:** ↑↓ (`update.ts` about line 376) calls `navOrder(deriveModel(state))`, then `withValidCursor` (`update.ts:67`) derives again, and `app.ts` renders with a third `deriveModel` unless the fast path applies. `renderPopup` builds a full DOM tree before `morph`.

**Do:**
1. Baseline: `npm run perf` at 500 / 2,000 / 5,000 tabs; save the output.
2. Memoize `deriveModel` per state object (a module-level `WeakMap<AppState, PopupModel>`; states are immutable, so identity is a safe key). Check that nothing mutates a state or model after deriving (grep for writes).
3. Re-run `npm run perf`, put before/after in the commit body. Commit: `perf: derive each state's model once`.
4. Real Chrome: `npm run dev`, open the gallery fixture with 2,000 and 5,000 tabs (add a `big` fixture if none exists) via chrome-devtools MCP, CPU throttle 4x, record a performance trace while holding ↓ for 2 s and while typing a 5-letter query. Report the longest frame and the p95 per interaction.
5. Write the numbers in `docs/v3-status.md` (a "3.0.1 measurements" section). Only optimize `renderPopup` / morph if a frame exceeds 16 ms at 2,000 tabs; if so, record the hot path in the trace and propose before changing.

## 8. Context-menu closes get ATO's undo (plan step 2)

**Where:** `src/background/worker.ts` `onMenuClick`: `chrome.tabs.remove(closing)` directly; the comment says undo is via Chrome's ⇧⌘T for now. Popup closes have ATO's undo (worker `restoreTabs`).

**Do:**
- One close path: move "recheck (item 1) → remove → record" into a worker-side module (e.g. `ui/chrome-close.ts`) used by both the popup (`ChromeBrowser.close`, via message to the worker like restore, with a local fallback as restore has) and the menu.
- The worker keeps the **last close record** `{ tabs, closedAt, message }` in `chrome.storage.session` (survives worker restarts, not browser restarts).
- Offering undo for a menu close: when the popup opens and a menu close happened within the last 60 s and hasn't been undone, show the normal undo toast ("Closed 3 duplicates · Undo"). Undo goes through `restoreTabs` (item 3) and clears the record. Write the choice and its reasoning in `docs/architecture.md`.
- Tests: `tab-menu.test.ts` keeps its properties; new tests: menu close then undo brings each tab back exactly once; record expiry; a second close replaces the first record.
- Fixture: popup opened with a pending menu-close undo.
- Commits: `refactor: one close path for popup and menu`, `feat: undo for right-click closes`.
